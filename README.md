# MDprev via JSproc

YAML・Markdown・Plaintextを、自分で書いたJavaScriptでMarkdownへ変換し、VS Code標準のMarkdownプレビューに表示する拡張機能です。

**変換はコマンド実行時だけ。入力やJavaScriptを保存・自動保存しても、変換しません。**

バージョン: 0.1.0（実機受入確認前）。デスクトップVS Code 1.105.0以降、ローカルフォルダのワークスペースが対象です。実際の画面操作・Windowsでの導入は未検証です。確認済みの範囲は [TESTING.md](docs/TESTING.md) を参照してください。

## インストールと最初の実行

1. VS Codeのコマンドパレットで `Extensions: Install from VSIX...`（拡張機能: VSIXからのインストール）を選び、`dist/mdprev-via-jsproc-0.1.0.vsix` を指定します。
2. 入力文書を置くフォルダをVS Codeで開きます。これが**利用ワークスペース**です。開発ソースのフォルダである必要はありません。
3. 利用ワークスペース直下に `transforms` フォルダを作り、同名ファイルがないことを確認して `examples/transforms/identity.cjs` を配置します。既存ファイルを置き換える場合は、元ファイルそのものを同じフォルダの未使用の `identity.backup-YYYY-MM-DD-NN.cjs` に改名して保全してから配置してください。
4. `.yaml` / `.yml` / `.md` / `.txt` のどれかを開きます。新規文書は一度保存してパスを確定させます。
5. `MDprev via JSproc: 変換処理を選択して実行` → `identity.cjs` を選びます。標準Markdownプレビューが横に開く設計です。
6. 入力を編集・保存した後、`MDprev via JSproc: 前回の変換を再実行` で更新します。プレビュー側にフォーカスがあっても前回の入力を使います。

最初は [実機確認手順](docs/ACCEPTANCE.md) の1〜6を実施してください。

## コマンド

| 表示名（すべて `MDprev via JSproc:`） | コマンドID | 動作 |
|---|---|---|
| 変換処理を選択して実行 | `mdprevViaJsproc.selectAndRun` | アクティブな入力を固定し、候補を選んで実行 |
| 前回の変換を再実行 | `mdprevViaJsproc.rerun` | 最後に成功した入力と処理を再利用 |
| 前回の結果を再表示（変換しない） | `mdprevViaJsproc.reopenPreview` | 保存済みの結果だけを開く |
| 実行中の変換を中断 | `mdprevViaJsproc.cancel` | 実行スレッドの終了を待って中断 |
| 診断ログを表示 | `mdprevViaJsproc.showLog` | ファイルパス、例外、実行環境、console出力を確認 |

ショートカットの初期割り当てはありません。VS Codeのキーボードショートカット画面で `MDprev via JSproc` を検索し、好みのキーを割り当ててください。

## 何が実行されるか

| 対象・操作 | 使用する内容 |
|---|---|
| 入力文書 | 処理を選択し終え、変換を開始した時点のVS Code文書内容。未保存編集を含む |
| 変換JavaScript・依存ファイル | ディスクの保存済み内容。未保存のJavaScript編集は使用しない |
| 変更・保存・自動保存 | 変換しない。VS Codeの自動保存設定も変更しない |
| 再実行 | アクティブな別ファイルを無視し、前回成功した入力・処理を使う |
| 失敗・時間切れ・中断 | 前回の成功結果と入力・処理の組を保持 |
| 空文字列の戻り値 | 正常な空の結果として表示。初回失敗とは区別 |
| 選択キャンセル | 実行しない。前回の記録も変えない |
| 実行中の追加コマンド | 拒否して案内。古い結果と新しい結果が競争しない |
| VS Codeの再起動 | 最後の成功結果と組をVS Codeのワークスペース状態から復元。自動実行しない |

入力が属するルートの `transforms` **直下**から `.js` / `.cjs` / `.mjs` を探します。サブフォルダ、`node_modules` 内、所定の `.backup-YYYY-MM-DD-NN` ファイルは候補にしません。補助モジュールは `transforms/lib/` などに置けます。複数ルートでも入力と同じルートだけを探します。

## 変換JavaScriptを書く

動作確認用の `identity.cjs` は次の内容です。具体的なYAML解析・業務変換は実装していません。

```javascript
module.exports = async function ({ text, filePath }) {
  return text;
};
```

- `text`: 入力文字列。YAMLも解析せずそのまま渡します。
- `filePath`: 入力ファイルの絶対パス。
- 戻り値: Markdownの文字列、または文字列に解決するPromise。
- `.cjs` はCommonJSです。`.mjs` は `export default` の関数を使います。
- `.js` は最寄りの `package.json` の `type` に従います。`type: module` のプロジェクトで上のサンプルを使う場合は `.cjs` のまま使ってください。
- 変換JavaScriptを追加・保存した後は、そのまま次の手動実行に反映されます。拡張機能の再ビルドは不要です。

### 外部npmパッケージ

利用ワークスペース側で必要なパッケージを導入します。`require` / `import` は変換JavaScriptの位置から通常のNode.js規則で解決します。拡張機能の開発用 `node_modules` は使いません。パッケージのインストールは拡張機能が自動実行しません。

実行環境は **VS Code内蔵Node.js** です。PCに別途入れたNode.jsではありません。診断ログに実際のバージョンを出します。純粋なJavaScriptパッケージを基本とし、ネイティブアドオンの互換性は保証しません。実行時のカレントディレクトリはワークスペースとは限りません。追加ファイルは `filePath` の親、CommonJSなら `__dirname`、ESMなら `import.meta.url` を基準に絶対パスへ解決してください。

## 設定

| 設定 | 初期値 | 意味 |
|---|---|---|
| `mdprevViaJsproc.transformsFolder` | `transforms` | 入力ルート内の相対フォルダ。ワークスペース外は不可 |
| `mdprevViaJsproc.timeoutMs` | `10000` | 強制停止までの時間。100〜300000ミリ秒 |

設定を変更しても変換しません。前回の再実行は、フォルダ設定変更後も記録済みの組を使います。別の処理に切り替える場合は「選択して実行」を使います。

## プレビュー、リンク、保持範囲

生成Markdownは `mdpjsp:` の読み取り専用仮想ファイルとして保持します。利用ワークスペースに生成Markdownや一時ファイルを作りません。標準プレビューをロックして開き、別のMarkdownタブへの追従を避けます。ロックを手動で解除すると標準プレビュー側の挙動が変わるため、そのまま使ってください。

相対パスは入力文書の場所を基準に扱います。仮想ファイルの画像・リンク先の読込を元ファイルへ接続する設計です。ただし **実画面でのリンク・画像表示は未検証** です。同じフォルダ以下の画像を初期対応範囲とし、`../` で入力フォルダの外へ出る画像や絶対 `file:` 画像は標準プレビューのアクセス制限により表示できない場合があります。ワークスペース外への読込は提供しません。仮想パス経由で開くリンク先は読み取り専用です。

固定するのは生成Markdown本文です。参照画像、外部URL先、テーマなどの外部状態まで凍結する機能はありません。

同じ入力への実行は同じ仮想URIを更新します。別入力の古い結果はそのセッション中は残りますが、VS Code終了後も復元するのは最後の成功結果1件です。ワークスペース状態を消すと、その結果も消えます。

## 実行権限と制約

未信頼のワークスペースではJavaScriptを実行しません。信頼する内容は利用者が確認してください。結果の再表示は実行を伴いません。

専用Workerは **セキュリティ用サンドボックスではありません**。変換JavaScriptはVS Codeと同じ利用者権限でファイル・ネットワークなどを扱えます。拡張機能自身は入力や変換JavaScriptを書き換えませんが、変換JavaScript自身の副作用までは禁止しません。

通常のJavaScriptの同期無限ループ・未完了Promiseは実際にスレッドを終了させます。ネイティブコードの停止不能な呼出し、変換処理が作った外部プロセス、既に完了した書込みの取り消しは保証しません。WorkerのV8旧世代ヒープ上限は256 MiB、Markdown結果はUTF-8換算16 MiB、診断ログに転送する標準出力・標準エラーは1回合計64 KiBまでです。

Web版、Remote/WSL/SSH、仮想ワークスペース、ワークスペースを開かない単独ファイル利用、未保存でパスのない新規入力は対象外です。

## 開発

```sh
npm ci
npm test
npm run test:integration
npm run package
```

ソースはJavaScriptで、コンパイルは不要です。VSIXの作成先 `dist/` は自動作成します。同名VSIXがある場合は新しいパッケージの生成後、元ファイルを同じフォルダの所定バックアップ名へ改名してから新版を配置します。配布用VSIXには開発依存パッケージを同梱しません。統合テストはVS Codeが起動可能な環境を要します。詳細は [設計](docs/DESIGN.md)、[工程表](docs/PROCESS_CHART.md)、[検証記録](docs/TESTING.md)、[実機確認](docs/ACCEPTANCE.md) を参照してください。
