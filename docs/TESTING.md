後者はVS Code配布物のNodeランタイムでのテストであり、拡張機能ホスト・GUI統合テストの合格ではない。

| 検証項目 | 方法と結果 |
|---|---|
| 4拡張子、日本語・絵文字・CRLF、絶対パス | 実ファイル・Worker・模擬VS Code文書で成功 |
| 未保存入力、未保存JavaScript | 入力の未保存内容を使用。JavaScriptは保存済み版を使用し通知。元ファイル不変 |
| 複数候補、直下探索、バックアップ除外 | 実ファイルで成功。補助サブフォルダを候補にしない |
| ワークスペース外・symlink | ルート外への探索・代理資源読込を拒否 |
| CommonJS / ESM / async | 実Workerで実行成功 |
| JS本体・CJS/ESM依存の再読込 | ファイルを書き換え、次の実行で反映することを確認 |
| npmの依存解決 | 利用側node_modulesのテスト用パッケージで成功。個々の外部パッケージの互換性試験ではない |
| 保存時の不実行 | 入力とJSの保存後もキャッシュと通知回数が不変。再表示で再実行しない |
| 前回の組、別タブ、複数ルート | 模擬APIで成功。アクティブファイルに取り違えない |
| 例外、構文エラー、非文字列、対象消失 | エラーとして終了。前回結果と組が残る |
| 初回失敗、選択取消、候補なし | 成功状態・空結果を作らない |
| 同期無限ループと未完了Promise | 実行開始のマーカーを確認し、1.2秒の試験用制限時間で終了。再試行成功 |
| 中断の実効性 | 実行開始後のファイル書込みが、取消完了後に増えないことを確認 |
| 成功後に残ったタイマー | Worker終了により残留しない |
| 二重実行 | 追加要求がbusyで拒否され、古い成功結果を保持 |
| Workspace Trust | 模擬APIで未信頼時の実行拒否を確認。実Restricted Modeは未検証 |
| 状態保存失敗、状態復元 | 保存失敗で前回を保持。復元後にJSがなくてもキャッシュ再表示可能（模擬状態API） |
| 読み取り専用・画像バイト代理読込 | providerの直接試験に成功。実画像レンダリングではない |
| 出力上限、ログ上限、空文字列 | 16 MiB超過は失敗、ログ64 KiB以内、空文字列は成功 |

最初の試験では模擬controllerの制限時間を300msに設定していたため、並行試験時のWorker起動時間を含め3件が失敗した。通常試験は製品と同じ10000msへ変更。終了しない処理の試験は別にし、実行開始を確認してから停止の実効性を検証した。製品の初期制限時間は変更していない。

## 標準プレビューの確認範囲

公式API、公式ソース、VS Code 1.105.1配布物から、仮想FS、変更イベント、`markdown.showLockedPreviewToSide` の登録とURIの扱いを確認した。

小規模プローブと統合テストを用意した。画面付き起動ではXサーバー・ソケットを利用できず、headlessではGTKが表示接続を必要として停止した。**統合テストは起動段階で阻害され、合格していない。** この環境制約を拡張機能の動作合格として扱わない。

次の確認はユーザー実機で行う:

- VSIXのWindowsでのインストールと拡張機能の起動
- 標準プレビューへの表示・更新、ロック、再表示
- 実際の自動保存時の非更新、プレビューにフォーカスがあるときの再実行
- 実際のウィンドウ再起動後の復元
- 同じフォルダ以下の相対画像・リンク
- Restricted Mode、Windowsのパス・外部npmパッケージ

手順は [ACCEPTANCE.md](ACCEPTANCE.md)。統合テストは表示可能な環境で `npm run test:integration` を実行する。`MDPJSP_VSCODE_VERSION` で対象バージョン、`MDPJSP_VSCODE_EXECUTABLE` で既存実行ファイルを指定できる。

## パッケージと納品

VSIXは `@vscode/vsce 4.0.0` で生成し、ZIP整合性・必須エントリ・ソースとの一致を検査する。パッケージ生成・CLI導入・Dropbox読戻しの実績とハッシュは別記 `DELIVERY.json` に記録する。パッケージ整合性と実機受入の合格を混同しない。
