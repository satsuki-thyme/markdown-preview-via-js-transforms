## 標準プレビューの確認範囲

0.1.0では公式API、公式ソース、VS Code 1.105.1配布物から、仮想FS、変更イベント、`markdown.showLockedPreviewToSide` の登録とURIの扱いを確認した。0.1.1では同版の標準Markdown Previewカスタムエディター登録と公開コマンド `vscode.openWith` の引数を確認し、URIとエディター種別で既存タブを探すよう変更した。

0.1.0検証時に小規模プローブと統合テストを用意したが、画面付き起動ではXサーバー・ソケットを利用できず、headlessではGTKが表示接続を必要として停止した。**GUI統合テストは起動段階で阻害され、合格していない。** 0.1.1では既存タブの再利用・閉じて再表示の検証を統合テストへ追加し、構文検査を実施した。GUIでの実行結果はない。

次の確認はユーザー実機で行う:

- 0.1.1導入後、プレビューにフォーカスして繰り返し再実行してもタブ・グループが増えないこと
- 入力側からの再実行、閉じて再表示、再起動後復元が維持されること
- [ACCEPTANCE.md](ACCEPTANCE.md) の残り16項目（画像・リンク、Restricted Mode、異常系など）

統合テストは表示可能な環境で `npm run test:integration` を実行する。`MDPJSP_VSCODE_VERSION` で対象バージョン、`MDPJSP_VSCODE_EXECUTABLE` で既存実行ファイルを指定できる。

0.1.0の自動テストはNode.js 24.19.0・VS Code内蔵Node.js 22.19.0で各17件成功だった。今回の各22件は既存17件にタブ再利用5件を追加したもの。
